## §1 확인한 사실 (Explore 조사 2026-11-17)

- 화면: `src/app/chat/page.tsx`(서버 컴포넌트, 최근 100개), `Composer.tsx`(한 줄 `<input>` + Send, `useOptimistic`), `DeliveryTimer.tsx`(1초마다 확인 후 `router.refresh()`), `actions.ts`(`sendMessage`, 답장 생성은 `after()`).

- 있는 것: 날짜 구분선(영어, `page.tsx:96-106`), 모든 메시지 아래 시각(en-GB 24h, `page.tsx:118`), 그가 보낸 사진(`<img alt="">`, 클릭 불가, `page.tsx:114`), 웹 푸시(`public/sw.js`, `settings/PushToggle.tsx`), 헤더 활동 문구("He's tied up right now…", `chat.ts:99-104`).

- 레이아웃 `max-w-md`(448px). 토큰은 `src/app/tokens.css`(라이트만, 글꼴·그림자·모션 토큰 없음).
- 가정: 사용자 다수는 iPhone Safari. iOS 웹 푸시는 홈 화면 추가 뒤에만 동작한다.

## §2 정의·계약 (구현 전 고정)

- **메시지 DTO**(`src/engine/chat-view.ts`): `{ id, sender: "user"|"char"|"member", text, mediaId: string|null, at: ISO(=deliver_at), replyTo: { id, sender, text(200자), mediaId }|null, reaction: emoji|null, status?: "read"|"delivered" }`. `status`는 내 마지막 메시지에만.
- **API** `GET /api/chat/messages`:
  - `?after=<id>` / `?before=<id>&limit=50` / `?around=<id>` (앞뒤 25)
  - 응답 `{ messages: DTO[], serverNow, wakeAt: ISO|null, typing: boolean, hasMoreBefore: boolean, activity: string }`. `wakeAt`은 다음 상태 변화(입력 중 시작 또는 도착) 시각이며 그 사이 내용·글자수는 싣지 않는다.
  - 남의 관계 id면 404.
- **묶음**: 같은 보낸 사람 연속, 간격 5분 이내. 시각은 묶음 끝에 한 번, 말풍선 탭 시 표시.
- **입력 중 창**: 서버가 `deliver_at - min(4s + 글자수×40ms, 12s)`부터 `typing:true`. 지연 0 답장은 생성 중 보낸 1~2초 뒤부터. 바쁜 상태면 없음.
- **읽음**: `seen_at`(W8)이 지났으면 `Read 9:41 PM`, 아니면 `Delivered`. W8 이전 행은 그의 다음 메시지 유무로 파생.
- **이전 대화**: 맨 위 근처에서 `before`로 50개, 스크롤 위치 보존.
- **슬롯 컴포넌트**(1파에서 null 반환으로 생성, 이후 파가 채움): `TypingStatus({typing})`, `PhotoBubble({mediaId, alt, onOpen, onReply})`, `ReactionBar({messageId, reaction})`, `QuotePreview({replyTo, onJump})`.
