## §1 확인한 사실

- 미국판 캐릭터 콘텐츠 구성(`content/characters/ihan/`): `bible.md`·`bible.yaml`(설정), `voice.md`(말투), `schedule.yaml`(일과), `diary/`, `scenes/`, `sns/`, `photos/`. 세계 설정 `content/world/`: `canon.jsonl`, `group.yaml`, `timeline.yaml`. 정책 `content/policy/guards.yaml`·`lines.md`. 검증 명령 `pnpm validate`.
- 지역 차단은 미국 일부 주만(`src/proxy.ts:9-12`). 일본은 막혀 있지 않다.
- 언어·캐릭터 의존 지점(Explore 조사 2026-11-17):
  - 캐릭터 id: 엔진은 `CHARACTER_ID = "ihan"` 상수(`src/engine/chat.ts:31`)를 chat·chat-view·reconcile·daily-affection·proactive가 공유. 앱 서버 쪽 `"ihan"` 리터럴: onboarding/actions.ts:55-64, him/page.tsx:16,29, me·settings 페이지·액션, admin/queries.ts:159, policy/reviewer.ts:86. `src/product`를 쓰는 곳은 chat/page.tsx·Composer·layout뿐.
  - 고정 문장: busy-overlay.ts(영어+한국어, `langOf`는 ko/en만, 이한 세계 고유명사 포함), output-guard FALLBACK(영어만), input-guard 위기 정규식(영어+한국어, **일본어 없음** — 안전 문제), SAFETY_SCRIPT(영어), activityLine(영어, chat.ts:99-104), chat.ts:216 무료 환불 집합(새 풀 추가 필요).
  - 규칙 정규식이 영어/한국어 전용: proactive PROMISE_RE, sulk resolvesSulk, profile RULES, breakers RULE_B1/B2·confirmsBreaker(llm 모드 프롬프트도 영어·"him"), secrets STRUGGLE. 대부분 mock/규칙 모드용이고 운영(llm 모드)은 LLM 프롬프트가 처리.
  - 기억: memory-extract llm 프롬프트가 "English sentence"로 저장 → 일본 사용자 "기억" 화면이 영어가 됨. selectMemories 단어 겹침(chat.ts:106-110)은 띄어쓰기 없는 일본어에서 거의 안 맞음.
  - persona 프롬프트: 한국어 머리말 + 영어 지시, 응답 언어 지시 없음(voice.md·bible이 결정). 세계 시각 KST — **일본(JST)과 시차 0**이라 그대로 맞다.
  - 사진 없는 캐릭터: photo-pick이 null → 텍스트만 저장(안전). /him은 자리 표시.
  - 서버 페이지 영어 하드코딩: settings·paywall($10)·privacy·ReconcileForm·i/[token]·onboarding·him·me·geo-block.
  - 테스트 다수가 "ihan"·영어 문장을 단언(chat, affection-sulk-breakup, breakers-golden, persona, proactive 등).
- 가정: 일본 사용자 대다수는 iPhone + LINE 사용자. iOS 웹 푸시는 홈 화면 추가가 필요(미국판과 같은 안내 사용).
