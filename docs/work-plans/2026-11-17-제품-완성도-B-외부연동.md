## 1. 결제 (가장 큰 결함 — 지금은 아무것도 팔 수 없음)

확인한 사실:
- `src/billing/stripe.ts`는 메서드 3개가 모두 `throw "Stripe 미구현"`. 운영에서 `getBillingProvider()`(`src/billing/index.ts:11-15`)가 이걸 돌려줘 Subscribe·Cancel 클릭 시 오류.
- `package.json`에 `stripe` 없음. webhook 경로 없음(`src/app/api`에는 chat·cron·media만). `handleWebhook` 스텁(`src/billing/provider.ts:6`).
- `entitlements`(`src/db/schema/billing.ts`): plan, dailyQuota, currentPeriodEnd, cancelAtPeriodEnd. **없음**: Stripe customer id, subscription id, status(past_due 등).
- 개발용 mock(`src/billing/mock.ts`, `/billing/mock-checkout`)은 dev 전용으로 잘 막혀 있음. 할당량 `src/engine/quota.ts`(무료 5/일, 유료 100/일, KST 자정 리셋), `DAILY_QUOTA_OVERRIDE` env는 운영에서 비워 둘 것.
- 가격: 미국 $10/월(decisions "유료 한도"), 일본 1,480엔은 사용자 OK 대기(decisions 백로그).

할 일: Stripe 계정·심사(등록 명칭·비성적 고정 문구 — 백로그 "Stripe 심사") → `stripe` 패키지 → Checkout(구독) + Customer Portal(해지·결제수단·영수증) + webhook(`checkout.session.completed`, `customer.subscription.updated/deleted`, `invoice.payment_failed`) → entitlements에 stripe id·status 컬럼(운영 DB 변경) → 실패 결제·유예·환불 처리, Stripe Tax(VAT/소비세). 일본판은 별도 Stripe 계정 또는 같은 계정 다른 가격.
- Vercel Marketplace에 Stripe 통합이 있으면 그것부터(세션 시작 시 Vercel `marketplace` 스킬로 확인).

## 2. 오류 모니터링·로그

- 후보: Sentry(Vercel Marketplace) 또는 Vercel 내장 관측. 새 패키지·계정 필요.

## 3. 안내 메일

- 메일 발송 서비스 없음(Clerk 인증 메일만). 필요한 것: 가입 환영(선택), 결제 영수증(Stripe가 대신 보낼 수 있음), 계정 삭제 확인.
- 후보: Resend(Marketplace). 결제 영수증을 Stripe 메일로 대신하면 1차는 생략 가능.

## 4. 그 밖에 계정·외부가 필요한 것

- Clerk 프로덕션 인스턴스(도메인 필요). Apple·Google 로그인 여부는 Clerk 대시보드 설정.
- 일본판 Vercel·Neon·Clerk 프로젝트 생성(사용자 OK 대기).
- 봇 차단: Vercel BotID 또는 Firewall 요청 제한(A는 DB 집계 기반 연타 제한만 함).
- 연령 외부 확인(Stripe Identity 등) — 백로그, 사용자 생긴 뒤.
- 환경 분리: AI Gateway 키를 운영·프리뷰가 공유, `.env.local` `DATABASE_URL`이 운영 Neon, GitHub Actions 선톡 cron URL이 `https://onday-blush.vercel.app` 하나로 고정(일본판 미포함).
- DB 백업·복구 절차 문서 없음(Neon 브랜치 기능으로 작성 가능, `docs/ops/`).
- 문의 이메일 주소 `SUPPORT_EMAIL`(A가 환경변수로 받게 만듦) — 사용자가 주소를 정해 Vercel env에 넣기.
