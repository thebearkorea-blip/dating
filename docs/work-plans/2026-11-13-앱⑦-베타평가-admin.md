설계와 다른 점
- `events.user_id`는 nullable(가입 전 `invite_link_open`은 사용자가 없음). `invite_link_open`은 `/i/[token]` "Start" 클릭(claim 액션) 시점에 기록(GET 렌더는 봇·새로고침으로 부풀어서).
- `day3_return`은 `/chat` 렌더 시 `users.created_at` 기준 3일 경과 첫 1회. `quota_exhausted`는 KST 하루 1회, `signup`·`first_message`는 사용자당 1회.
- `paywall_shown`은 `takePaywall`(billing/paywall.ts), `subscribe`/`cancel`은 mock 결제(billing/mock.ts)에 기록. Stripe 웹훅은 아직 스텁이라 미연결(연결 시 같은 1줄).
- llm_usage는 사용량이 응답에 있을 때만 행을 남긴다(주입 mock llm은 기록 없음, mock 공급자는 0 토큰 0원 행).
- 미연결: `src/tools/{diary-draft,diary-approve,review}`·`src/policy/reviewer.ts`의 `complete()`(DB 없는 CLI, weekly-metrics.md에 이미 기록). `review` purpose는 타입만 있음.
- 평가 탭의 "persona 단계"는 평가 시점이 아니라 현재 관계 stage. 사용자 탭은 단계·플랜·최근 활동만(affection은 싣지 않음).
- Neon 전환 시 `role_app`에 billing 읽기 GRANT가 없어 /admin 비용·사용자 탭이 막힌다(roles.sql 미수정).
