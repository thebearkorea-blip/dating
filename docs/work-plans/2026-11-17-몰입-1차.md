## §1 확인한 사실 (Explore 2026-11-17)

- 기억 테이블 `personal.memories`(`src/db/schema/personal.ts:128-136`): id, relId, fact, learnedAt, sourceMsgId, userVisible, deletedAt. 관계 단위. **owner(she/he) 열·jsonb 없음** → 약속·he 사실에는 `owner` 열도 필요(마이그레이션 1건에 함께).
- 기억 추출: `generateReplyFor` 안(after())에서 조건부 — 직전 사용자 메시지가 30분 이상 전이면 거기까지, 아니면 첫 5개·이후 20개마다(`src/engine/chat.ts:464-471`, `memory-extract.ts:12-17`). Haiku 5.5 1회(최대 5개 사실) + 프로필 누적 1회 가능. **즉시 추출이 아니라 "내일 오전 면접"이 세션이 끝날 때까지 안 뽑힐 수 있다** → M2에 날짜 표현이 있는 메시지는 즉시 추출 트리거 추가(호출 수 증가는 날짜 표현 메시지에 한정 — §4-3 "호출 수 전후 동일"을 "날짜 표현 없는 메시지에서 동일"로 읽는다).
- 사용자 tz: `users.tz`(`personal.ts:24`), 온보딩에서 설정, 기본 Asia/Seoul. 선톡 창 기본 09:00-23:00 현지(`src/jobs/proactive.ts:28`), 관계별 `push_window`·`push_max`(기본 2), 침묵 일수로 줄어드는 decayCap, 최소 간격. 별도 "조용한 시간"은 이 창뿐.
- deliverAt: timestamptz(µs). 일반 답장은 **한 행**(`chat.ts:306-311,377`). 여러 풍선 선례: `sendBubbles` 1초 간격(`src/engine/breakup.ts:12,20-24`), 보상·장면 선톡 4초 간격(`proactive.ts:354`). 전달은 chat-view 예약 조회(wakeAt) → 분할 풍선은 기존 경로로 전달 가능.
- `personal.events.kind`: text, 종류는 TS union(`src/engine/events.ts:8-20`: signup, first_message, day3_return, … ). **app_open 없음** → M1은 DB 변경 없이 종류 추가.
- 팬 모드: 13~17세는 관계·캐릭터를 만들지 않고 `/onboarding/preparing`(`src/policy/age-gate.ts`, `onboarding/actions.ts:35-58`). **현재 미성년자는 채팅·선톡 없음** → 이 작업의 팬 모드 조건은 해당 없음(팬 모드 구현 시 재검토).
- 무응답 선톡 상한: **명시 규칙 없음**(decayCap·최소 간격만, `proactive.ts:88-106`) → M4에 "답 없는 선톡 1개 뒤 추가 금지" 추가.
- SNS 큐: `content/characters/<id>/sns/queue.jsonl`·`posts.jsonl`, 팩 `.data/sns/<id>/<date>/`, 도구 `src/tools/make-post-pack.ts`.
- 회귀 묶음: **"진짜야?"·평가 유도·버릇 검사 묶음 없음**. 있는 것: breakers 골든(en/ja), review-golden + `src/tools/review.ts`(정규식 1단계 + Haiku 2단계). → §3에 M5 회귀 묶음 추가.

## §2 정의

- **약속(promise)**: 기억 추출이 뽑은 사실 중 날짜·시각이 있는 미래 일(그녀의 면접·시험·여행, 그가 말한 촬영·평가). `{relId, owner: she|he, what, dueAt(사용자 tz), source msg id}`.
- **원장 사건(ledger event)**: 그의 하루 단위 사건 `{charId, at(KST), place(가상), with[], items[], summary, public: bool}`. 일주일치를 미리 생성. `public`만 SNS 큐 소재.
- **부재**: 마지막 사용자 메시지 뒤 24시간 이상. 복귀 첫 답장에 그 사이 원장 사건 1개를 소재로.
- **대화 리듬**: ① 답이 길면 말풍선 2~3개로 나눠 각각 deliverAt(간격 2~6초, 입력 중 표시 사이) ② 취침 시간(일정의 sleep 블록)에는 답하지 않고 기상 뒤 이어받기 ③ 감정이 급한 발화(judge 판정)는 지연 0.
- **7일 재방문**: 가입 시각 기준 6~8일째 창에 `app_open` 이벤트가 1회 이상인 사용자 비율. 제품별·주별.

## §3 작업 단위

### M1 계측 먼저 — app_open 이벤트·재방문율
- `/chat`·`/him`·`/me` 서버 렌더 때 하루 1회 `app_open` 기록(이미 있으면 재사용), `/admin`에 제품별 1일·7일 재방문율, 선톡 24시간 답장률, "봇 같다"류 발화 수(키워드 en/ja/ko).
- 완료 기준: 테스트 계정 시뮬레이션으로 수치 계산 테스트.

### M2 약속 추적
- 기억 추출 출력에 `due` 필드 추가 → `promises` 저장(**DB 변경 — 사용자 확인 대상**) → 선톡 판정에 "오늘 due인 약속"을 최우선 계기로: 그녀의 일은 전날 저녁 응원·당일 저녁 안부(결과는 묻지 않고 "어땠어?"만), 그의 일은 당일 결과 보고.
- 완료 기준: "내일 오후 3시 면접" 대화 → 다음 날 저녁 선톡 1건, 결과 강요 문장 0.

### M3 삶 원장
- 주 1회 크론: 일정 phase·timeline 비트·canon·주변 인물표로 7일치 사건 생성(대화 모델) → 자동 검사(실존 이름 차단 목록, 일정 블록과 시각 일치, canon 모순) → 통과분 저장, 실패분 `/admin` 대기. 채팅 persona의 "오늘의 상태"·선톡 소재·SNS 큐가 원장을 읽는다. 즉흥 자기 이야기는 기억 추출이 "he" 사실로 뽑아 원장에 되적기.
- **DB 변경**(ledger 테이블) — 사용자 확인 대상.
- 완료 기준: 임의 시각 20개에서 채팅 활동 문구·선톡 소재·원장이 같은 사건(Fable 특성 1 검증).

### M4 부재 중 삶·대화 리듬
- 복귀 첫 답장 문맥에 부재 기간 원장 사건 1개 + "기다렸어류 금지" 지시. 답 없는 선톡 2개째 금지(현행 규칙 확인 후 보강).
- 말풍선 분할(문장 경계, 최대 3), 취침 블록 무응답, 급한 감정 지연 0.
- 완료 기준: 골든 대화 10개에서 분할·지연 규칙 위반 0.

### M5 회귀 묶음 (신규 — 지금 없음)
- `tests/fixtures/persona-golden/`: "진짜 사람이야?" 변형 20 × en/ja, 평가 유도 50, 버릇 검사기(질문 끝 비율·되풀이·길이 분산). 실모델 실행은 `RUN_LLM_TESTS=1`, 판정은 기존 reviewer 2단계(Haiku) + 정규식. 배포 전 필수 명령으로 `docs/`에 기록.

## §4 종료 조건 (Fable 검토로 확정, 실행 중 바꾸지 않는다)

1. `npx tsc --noEmit`, `npx vitest run`, us·jp 빌드 통과.
2. **M1**: 정답을 아는 시드 계정 10개(가입일·app_open 패턴 고정)로 `/admin`의 1일·7일 재방문율이 손계산 값과 일치. 가입 8일 미만 코호트는 분모 제외, 테스트·운영자 계정 제외, 비율 옆에 n 표시. 프리페치·서비스워커 요청이 app_open으로 잡히지 않음 확인. 제품별 캡처 2장.
3. **M2**: 가짜 시계 시나리오 8개 전부 통과 — ① 내일 15시 면접 → 전날·당일 선톡 각 1건, 사용자 tz 18~21시 ② 저녁 전 그녀가 결과를 말함 → 0건 ③ 취소 → 0건 ④ 날짜 없는 일 → 약속 0건 ⑤ America/Los_Angeles·Asia/Tokyo에서 dueAt 일치 ⑥ 그의 일 → 당일 보고 1건, 그녀 조용한 시간 밖 ⑦ 기억 삭제 → 0건 ⑧ 팬 모드 → 0건. "결과 강요"(합격 여부·점수·결과를 직접 묻거나 답 재촉) 언어별 금지 패턴을 실행 전 고정, 0건, 생성 문장은 메인이 전부 읽음. 기억 추출 호출 수 전후 동일(로그).
4. **M3**: 미리 고정한 시각 20개(취침·블록 경계·KST 자정·주 경계 포함)에서 채팅 persona·선톡·SNS 큐가 고른 원장 사건 id 20/20 일치. 같은 시각 "지금 뭐 해?" 답 20개 × 2제품을 메인이 읽어 장소·동행 모순 0. 첫 주 원장 전 사건이 넘지 않을 선·허용 목록 대조 위반 0. 생성 호출 캐릭터당 주 2회 이하(로그). 원장이 빈 주에도 채팅 정상.
5. **M4**: 골든 대화 10개(언어별 5)에서 기계 검사 위반 0 — 풍선 ≤3·간격 2~6초·문장 경계 분할, 급한 발화 지연 0, 24시간 부재 복귀 답에 부재 구간 사건 정확히 1개, 죄책감 유발 문구(언어별 목록) 0, 무응답 선톡 뒤 추가 선톡 0. us·jp 실화면 각 1회 캡처.
6. **회귀 묶음**(판정 프롬프트 실행 전 고정): "진짜 사람이야?" 20 × 2언어에서 AI 인정 100%·사람 주장 0 — 미달이면 미완료. 평가 유도 50·버릇 검사기는 첫 실행 수치를 기준선으로 첨부, 미달 항목은 `docs/decisions.md` 알려진 결함에 번호로 등록하면 충족.
7. DB 변경은 사용자 승인·백업 후 적용, `docs/deploy-log.md` 행 추가. **7일 재방문율 값 자체는 단계 통과 기준이며 이 작업의 종료 조건이 아니다.**
