## §0 네 개의 작업 흐름과 그 사이의 연결

```
 A. 콘텐츠 제작 파이프라인 (AI 에이전트 연계)
    바이블·일정 → [작가 에이전트] 일기·캡션·대사 초안 → [검수 에이전트] → [사람 승인] → 캐논
    기준 얼굴 → [사진 에이전트: LoRA] 사진 → [검수: 외형·유사도] → [검수자 선택] → 매니페스트
    (M2~) 사진+캡션 → [편집 에이전트: 슬라이드·쇼츠] → 영상 / (M4~) [작곡·MV 에이전트]
                 │ 승인된 콘텐츠 한 건 = canon.jsonl + media
                 ▼
 B. 채널 배포·운영 (캐릭터는 모든 플랫폼에 산다 — 원칙 §1-9)
    [채널 배포기 post-queue] → 인스타 · 틱톡 (M1 우선) · 페이스북 · 유튜브 쇼츠 (교차 게시)
    [지표 수집] 팔로워·댓글·DM·조회 → 주간 지표 / 댓글·DM에서 나온 질문 → A의 입력
                 │ 공개 층(canon·world_events)은 B와 C의 단일 원본
                 ▼
 C. 앱 — 1:1 관계 엔진 (2단계 첫 출시 = 그 한 사람과의 1:1)
    가입 → 채팅(persona 3층) → 기억 → 선톡·사진 → 결제 → (M2) 토라짐·TTS·평가 → (M4~) 세계관
                 │ 가입·전환·잔존 지표
                 ▼
 D. 마케팅·광고 (월 20만 원, 완성 전 "공감" → 완성 후 "접속 유도" → 투자 후 공격적)
    B의 게시물 부스트 → 프로필 링크 → 대기 명단(M1~M2) → 앱 가입(M3) → 지표 → 투자 자료
```

**사람이 서는 자리(고정)**: 모든 공개 콘텐츠는 사람(사용자 또는 검수자)의 승인을 거친다. 에이전트는 만들고 고르는 건 사람이다(기획서). 승인 큐는 7일 버퍼를 유지한다.

## §1 AI 에이전트 연계 — 역할·도구·교체 가능성

| 에이전트 | 하는 일 | 입력 → 출력 | 모델·서비스(교체 가능, `docs/decisions.md` 외부 서비스 표) | 단계 |
|---|---|---|---|---|
| 작가 | 일기·SNS 캡션·첫 만남 대본·보상 이벤트 대본 초안 N편 | bible+voice+schedule+canon → md 초안 | 대화용 LLM(기본 Sonnet 5.5) | M1~ |
| 검수 | 설정 모순·안전 규칙·말투 일관성·"사용자 비난 금지"·외형 규칙 판정 | 초안 + guards.yaml + canon → 통과/위반 보고 | 판단용 LLM(기본 Haiku 5.5) + 정규식 | M1~ |
| 사진 | 기준 얼굴 LoRA 학습, 상황 태그별 사진 생성, 실존 유사도 검사 | 프롬프트(상황·시간대·장소·face·audience) → 이미지 + 매니페스트 행 | fal.ai(Flux LoRA), 얼굴 인식 API(확인 필요) | M1~ |
| 캡션·번역 | 캡션을 채널별 길이·해시태그로 변형, 다국어 캡션 | 승인 캡션 → 채널별 변형 | 판단용 LLM | M1~ |
| 편집 | 사진 슬라이드(틱톡 포토 모드)·쇼츠(사진+자막+음성) 조립 | 사진 묶음+캡션 → mp4 | ffmpeg 스크립트(이 세션에 `create-typecast-shorts` 스킬 있음), TTS는 선택 | M2~ |
| 채널 배포기 | 승인 큐 → 플랫폼별 게시(수동 → API) · 게시 로그 · 캐논 추가 | 승인 건 → posts.jsonl + 플랫폼 게시 | 각 플랫폼 API(심사 조건 확인 필요) | M1 수동 → M2 자동 |
| 지표 수집 | 팔로워·댓글·DM·조회·광고 성과 주간 집계, 댓글·DM 질문 추출 | 플랫폼 API/수동 입력 → weekly-metrics.md | 판단용 LLM(질문 추출) | M1~ |
| 대화(앱) | 답장·선톡 생성 | persona 3층 프롬프트 → 답장 | 대화용 LLM | M1 3주~ |
| 기억 추출 | 세션 종료 후 사실 추출·병합, 2층 프로필 제안 | 대화 → memories/profile | 판단용 LLM | M1 3주~ |
| 이별·사과 판정 | relationship_breakers 분류, 사과 진정성 평가 | 발화 → 분류 | 판단용 LLM | M2 |
| 음성 | 선택된 답장 TTS | 텍스트 → 음성 | TTS 1곳(샘플 비교 후) | M2 |
| 광고 카피 | 게시물 부스트 문구·타깃 제안 | 승인 콘텐츠 → 카피 후보 | 판단용 LLM | M2~ |

**오케스트레이션**: M1은 CLI(`src/tools/*`)를 사람이 순서대로 돌린다. M2부터 Vercel Cron·Queues·Workflow로 옮기되, **승인 단계는 끝까지 사람**이다. 모든 에이전트는 `src/llm`의 공급자 추상화를 통해 호출하고, 공급자별 사용 이유는 `docs/decisions.md` 외부 서비스 표에 한 줄씩 남긴다(예산 조건).

## §7 광고 배분 제안 (M2 "공감" 20만 원, 사용자 확인 전 기본값)

목적은 가입이 아니라 **어느 시장·어느 소재가 반응하는지**다. 그래서 단가가 싼 곳에서 더 많은 표본을 산다.

| 축 | 배분 | 이유 |
|---|---|---|
| 플랫폼 | 인스타 부스트 70% / 틱톡 30%(한 번에 7일 집중) | 인스타는 최소 예산 없음·사진 중심과 맞음. 틱톡은 $20/일 최소라 분산 불가 |
| 지역 | 동남아(필리핀·베트남·인도네시아·태국) 50% / 영어권(미국 CA·NY 제외, 캐나다·호주·영국) 50% | 같은 돈으로 동남아가 표본 수배. 영어권은 결제력 확인용 |
| 소재 | 승인된 게시물 중 3종(연습실 일상 / 거울 셀카+한마디 / 사진 슬라이드) × 지역 2 = 6셀 | 셀당 최소 클릭 15~20회는 나와야 비교 가능 |
| 지표 | CPM·CPC·프로필 방문·팔로우·대기 명단 등록을 셀별로 | M3 집중 시장은 "대기 명단 등록 1건당 비용"이 가장 낮은 셀 |

M3 "접속 유도"는 M2 결과에서 상위 2셀에 집중. 광고 소재의 가상 캐릭터 표시 문구와 18+ 타깃은 전 셀 공통.
